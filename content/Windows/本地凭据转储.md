### （扩展知识）GPP 与 LAPS

为了防止利用共享管理员密码的攻击，微软在 Windows Server 2008 中引入了组策略首选项（GPP），其中有集中更改本地管理员帐户密码的功能等。但其数据存储在SYSVOL，虽然进行了AES-256加密，但是微软将AES私钥公开到了MSDN文档中。后被利用（Get-GPPPassword）。

微软在 2014 年发布了安全更新 (MS14-025)，取消了创建包含密码的组策略首选项的功能。虽然这些文件无法再创建，但包含密码的现有组策略首选项并未被删除，这意味着有些可能仍然存在。

为了再次解决集中管理本地管理员帐户密码的问题，微软于 2015 年发布了本地管理员密码解决方案 (LAPS)，它为加入域的计算机的本地管理员密码提供了一种安全且可扩展的远程管理方式。
LAPS 使用 `admpwd.dll` 更改本地管理员密码，并将新密码推送到相关计算机对象的 `ms-mcs-AdmPwd` 属性。

> [!note] 找到有权限能访问 `ms-mcs-AdmPwd` 属性的账户——他们可以读取使用 LAPS 管理的机器上的本地管理员的明文密码。



## LSA Secrets

> **SAM** 侧重“本机用户密码哈希”，**LSA Secrets** 侧重“系统运转过程中产生的各种口令/密钥”。

LSA Secrets 被保存在：
- 注册表：`HKLM\SECURITY\Policy\Secrets`
- 文件：`%SystemRoot%\System32\Config\SECURITY`

`HKLM\SECURITY` 中存储了明文密码、域缓存凭证、NTLM 哈希等形式的凭证，**各种系统级敏感信息**：
- 服务账户、计划任务等的明文/可解密密码
- 已登录域用户的缓存凭证
- IE / SQL 等应用密码
- 部分系统密钥 (e.g. DPAPI master key)。


*导出方法类似前面的 SAM。*

### 内存转储

方法：
1. 任务管理器右键 `lsass.exe`
2. SysInternals 的 `ProcDump` 从命令行创建转储文件
3. 但由于 `ProcDump` 可能也具有可识别的签名——构建自己的代码来创建转储文件（MiniDumpWriteDump）

Mimikatz 解析 LSASS dump 时，必须在相同架构（x64 vs x86）且**尽量接近的操作系统版本**上进行（最好是相同补丁级别或接近版本），否则结构体偏移可能不一致，导致解析失败或数据错误。处理 dump 文件时为**离线操作**，因此**不需要以管理员身份运行命令提示符，也无需启用 `privilege::debug` 权限。**

#### MiniDumpWriteDump

当任务管理器和 `ProcDump` 创建转储文件时，它们会调用 Win32 MiniDumpWriteDump API。这意味着我们可以用 C# 编写自己的应用程序来执行相同的操作。

现在这个方法也会被检测。



## 离线处理凭据

不需要上传 mimikatz 到目标机器——转储所需的目标机器上 LSASS 的部分内存到我们的机器。

一般内存转储都被检测——可以看看 BOF [nanodump](https://github.com/fortra/nanodump)（可以在进程内导出 lsass，避免了工具落入文件系统，通过反射式加载在进程内执行导出行为）然后魔改？
Linux 上 mimikatz 的替代品：pypykatz（可解析 lsass dump）
